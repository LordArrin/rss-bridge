TG WS Proxy is a highly specialized proxy designed to bypass Telegram network blocks (e.g., via DPI) by tunneling traffic through Cloudflare. It has been specifically adapted for RSS-Bridge with native SOCKS5 support.

  • Targeted Bypass. Solves Telegram-specific blocking without routing your entire RSS-Bridge traffic through a heavy VPN or general-purpose proxy.
  • Cloudflare Tunneling. Uses Cloudflare infrastructure to mask the origin IP and bypass Deep Packet Inspection (DPI) systems.
  • Native SOCKS5 Integration. Built-in SOCKS5 server specifically configured to work seamlessly with the RSS-Bridge Telegram bridge.
  • Hardened Security. Runs with a read-only filesystem, no-new-privileges, and isolated tmpfs mounts to minimize the attack surface.

Quick start

  1. Add TG WS Proxy to your docker-compose.yml: 
    services:
  tg-ws-proxy:
    image: lordarrin/tg-ws-proxy:latest
    container_name: tg-ws-proxy
    restart: unless-stopped
    network_mode: host
    environment:
      - PROXY_HOST=192.168.1.1        # Your local MTProto proxy host
      - PROXY_PORT=443                # Your local MTProto proxy port
      - PROXY_SECRET=your_secret_here # MTProto proxy secret
      - CFPROXY_WORKER_DOMAIN=rough-unit-*.workers.dev
      - KEEPALIVE=true
      - SOCKS_ENABLED=true
      - SOCKS_HOST=192.168.1.1        # Host IP reachable by RSS-Bridge
      - SOCKS_PORT=1080               # Port for RSS-Bridge to connect to
      - SOCKS_USER=your_socks_user
      - SOCKS_PASS=your_socks_pass
    security_opt:
      - no-new-privileges:true
    read_only: true
    tmpfs:
      - /tmp:noexec,nosuid,size=64m
      - /home/app/.cache:noexec,nosuid,size=32m
  2. Register the proxy profile in RSS-Bridge config/config.ini.php: 
    [proxy_profile_tgws]
type = "TgWS"
socks_url = "socks5h://your_socks_user:your_socks_pass@192.168.1.1:1080"
connect_timeout = 10
request_timeout = 30
retries = 3
  3. Restart the stack (docker compose up -d) and select Use proxy in the settings of the Telegram bridge.

Deployment Options

Choose the Cloudflare routing method that best fits your infrastructure:

  • Cloudflare Worker — The simplest method. Uses a free workers.dev subdomain. No custom domain or DNS configuration required.
  • Cloudflare Proxy — Requires your own domain routed through Cloudflare. Provides more control and custom branding, but involves manual DNS and SSL configuration.

Configuration options

Variable Purpose
PROXY_HOST / PORT / SECRET Credentials for your local MTProto proxy that the tunnel will forward traffic to.
CFPROXY_WORKER_DOMAIN The active Cloudflare Worker or Proxy domain used to bypass DPI blocking.
SOCKS_ENABLED Must be true to expose the SOCKS5 port for RSS-Bridge.
SOCKS_HOST / PORT / USER / PASS The SOCKS5 endpoint details. HOST must be an IP reachable by the RSS-Bridge container.
💡 Important Networking Note: Because this container uses network_mode: host, it does not have its own isolated Docker network IP. When configuring socks_url in RSS-Bridge, you must use the IP address of the host machine (e.g., 192.168.1.1) or host.docker.internal, not the container name tg-ws-proxy.
⚠️ Scope Limitation: This proxy is highly specialized for Telegram traffic. Do not attempt to use it for general web scraping or other RSS-Bridge endpoints. For general Cloudflare bypass, use Trawl or FlareSolverr.

Troubleshooting

  • Connection refused — RSS-Bridge is trying to connect to the container name instead of the host IP. Update the socks_url in config.ini.php to use your host machine's actual IP address.
  • Worker error / 502 Bad Gateway — Verify that your CFPROXY_WORKER_DOMAIN is correctly deployed in Cloudflare and that the PROXY_SECRET matches your MTProto proxy.
  • Authentication failed — Double-check that SOCKS_USER and SOCKS_PASS in the compose file exactly match the credentials in your RSS-Bridge socks_url.

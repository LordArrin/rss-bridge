FlareSolverr is a proxy server to bypass Cloudflare protection using a headless Chrome browser. It is the classic solution for Cloudflare bypass and works out of the box for most sites:

  • Cloudflare specialist. Designed specifically for Cloudflare challenges — Turnstile, JavaScript challenge, and "Checking your browser" pages are solved automatically.
  • Session support. Named sessions keep cookies between requests, so once a challenge is solved, subsequent requests are much faster.
  • Zero configuration. A single Docker container and two lines in config.ini.php — no API keys or external services required.

Quick start

  1. Add FlareSolverr to your docker-compose.yml alongside RSS-Bridge (no exposed ports — it stays inside the Docker network): 
    services:
  flaresolverr:
    image: ghcr.io/flaresolverr/flaresolverr:latest
    container_name: flaresolverr
    environment:
      - LOG_LEVEL=info
    shm_size: '1gb'
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8191/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 30s
    restart: unless-stopped
  2. Register the proxy profile in config.ini.php: 
    [proxy_profile_flaresolverr]
type = "FlareSolverr"
url = "http://flaresolverr:8191"
timeout = 60000
session_name = "rss_bridge_session"
  3. Restart the stack (docker compose up -d) and select FlareSolverr in the Proxy profile dropdown of any bridge that supports it.

Configuration options

Option Default Purpose
url — (required) FlareSolverr address inside the Docker network
timeout 60000 Maximum time per request, in milliseconds
session_name rss_bridge_session Named browser session that reuses solved challenges across requests
💡 Note: Sessions dramatically speed up repeat requests. The first request to a Cloudflare-protected domain may take 10–30 seconds (challenge solve), while subsequent requests to the same domain finish in 1–3 seconds thanks to the stored clearance cookies.
⚠️ Limitations: FlareSolverr solves only Cloudflare challenges. Other protections (Akamai, PerimeterX, Datadome, Anubis, etc.) are not supported. For wider coverage and better performance, consider Trawl.

Troubleshooting

  • FlareSolverr unavailable — the container is not running or the url is wrong. Check docker compose ps and the health status.
  • Session error in logs — the session cache became stale. RSS-Bridge automatically invalidates it and retries; if it persists, restart the FlareSolverr container.
  • Timeout on first request — heavy Cloudflare challenges can take longer than the default 60 seconds. Increase timeout in config.ini.php to 120000 or more.

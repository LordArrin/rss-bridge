This bridge follows chapter updates of a work on Author.Today. It reads the same internal reader API that the site's own reader uses, so no browser, proxy or JavaScript engine is required.

  • Two modes, never mixed. Either chapter previews (newest chapters with cover and work status) or full chapter text (text only, no cover and no statistics).

  • Free content only. Paid, locked and suspended chapters are skipped — the bridge never bypasses the paywall.

  • Early-access friendly. Works that open chapters after a delay are handled correctly: paid chapters are skipped and the next readable ones are collected instead.

  • Polite request budget. One work page plus at most 8 chapter requests per generation, with a random 1–3 second pause before every chapter fetch.

  • Adult content handled. The AdultUser=true cookie is always sent — exactly what the site's "Yes, I am 18" button does.

  • Reader-friendly markup. Author-specified text colours are stripped so the text stays readable in dark themes, images become responsive block elements, links are absolutised.

  • Optional account access. Three cookies unlock what your account can already read legally. The account ID is detected automatically.

Configuration

Anonymous reading works out of the box — no configuration is needed. Account cookies are optional and only add content your account already has access to (for example chapters you have purchased).

  1. Log in to author.today in your browser.

  2. Open developer tools (F12) and go to Storage → Cookies (Firefox) or Application → Cookies (Chrome), then select https://author.today.

  3. Copy the values of LoginCookie, TrustedToken and ngLoginCookie. Only the values are needed — the bridge adds the cookie names itself.

  4. Add them to your /config/.bridges file in the [AuthorTodayBridge] section:

    [AuthorTodayBridge]
login_cookie = "your-LoginCookie-value"
trusted_token = "your-TrustedToken-value"
ng_login_cookie = "your-ngLoginCookie-value"

  5. Restart your RSS-Bridge container to apply the configuration:

    docker restart rss-bridge

💡 Note: The user_id option is optional and normally not needed — the bridge reads your account ID from the work page automatically. Set it only if the log reports Failed to decode the chapter text. A wrong value takes precedence over auto-detection and breaks decoding, so leaving it out is the safest choice.

⚠️ Security: These cookies are effectively keys to your account. Never share them or paste them into public issue reports. They are stored only in your local /config/.bridges file and are sent only to author.today. Cookie values are never written to the log — only cookie names.

How reading works

  1. The work page /work/{id} provides the title, author, cover, work status and the chapter list with publication dates.

  2. Each chapter is fetched from /reader/{workId}/chapter?id={chapterId}, which returns JSON with an obfuscated text payload.

  3. The payload is XOR-encoded over UTF-16 code units. The key is the reversed Reader-Secret response header, followed by @_@ and the account ID (empty for anonymous sessions).

  4. The account ID is read from app.setOptions({ … userId: … }) on the work page, which is requested with the same cookies as the chapter — so both sides always agree on the identity.

  5. If the account key produces no valid HTML, the anonymous key is tried as a fallback. If neither works, the bridge raises an error instead of caching unreadable text.

Bridge parameters

  • Story ID: Numeric work ID (e.g. 230933) or a URL — both https://author.today/work/230933 and https://author.today/reader/230933/6583841 are accepted. Other hosts are rejected.

  • Disable tags: Do not attach the work's tags as item categories (enabled by default).

  • Fetch full chapters: Switch the feed from previews to full chapter text. When enabled, the feed contains only readable full texts — no covers, no statistics, no preview padding.

  • Chapters with full text (max 3): How many full chapters to deliver (default: 3, hard maximum: 3). Only successfully decoded chapters count towards this limit; paid ones are skipped and the bridge continues down the chapter list.

Caching

  • Feed: 15 minutes.

  • Readable chapter text: 7 days — published chapters do not change, so repeat generations need only the work page request and no pauses.

  • Paid or otherwise unavailable chapters: 1 day, so early-access chapters are re-checked once they open for free.

  • Cache keys include the session identity, so adding or removing account cookies never serves text decoded for a different identity.

Troubleshooting

The bridge logs which key actually worked, so you can tell account access from an anonymous fallback:

docker logs rss-bridge | grep AuthorTodayBridge

  • decoded with the account key (user_id …) — your cookies work, account access is active.

  • fell back to the anonymous key - auth cookies did not take effect — the session has expired; copy fresh cookies from the browser.

  • auth cookies are set but the page reports no user_id — same cause, detected already on the work page.

  • Failed to decode the chapter text — set user_id in the configuration (take the value from the user_id detected on the work page log line).

  • No freely readable chapters found — all recent chapters are paid; they will be re-checked after a day.

💡 Tip: Chapters served from the cache are logged at DEBUG level only, so a repeat generation within the cache window shows no new key check. Restart the container (or wait for the TTL) to see a fresh decode, and set LOG_LEVEL=debug for the full picture.
